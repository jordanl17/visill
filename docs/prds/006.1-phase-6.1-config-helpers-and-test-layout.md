# Phase 6.1 - defineVisillConfig defaults + test layout standardization

Status: Shipped 2026-05-27. Owner: jordan.lawrence@sanity.io. Date: 2026-05-27.

## Goal

Make the Phase 6 template actually build end-to-end as scaffolded, and bring all packages onto a single test layout. Re-green the CI gates that Phase 6 push left red.

## Why this is a follow-up

Phase 6 shipped `create-visill` + the canonical template + the vendored decision-tree integration gate. The gate worked exactly as ADR 0017 promised: it caught two real gaps before they reached downstream consumers.

1. `defineVisillConfig({})` is incomplete. It sets `viteSingleFile`, css transformer, and terser options, but does not configure `root`, `build.rollupOptions.input`, `build.outDir`, or wire the `finalizeBundle` / `assembleSkill` plugins. The vendored example compensates with explicit Vite config; the scaffolded template uses the minimal call and fails with `Could not resolve entry module "index.html"`.

2. `visill` colocates tests in `src/*.test.ts`; the other three packages separate tests under `test/`. ADR 0024 standardizes on separate `test/` directories.

Both are Phase 3 / Phase 1 design gaps that the integration gate exposed during the Phase 6 push. Splitting them into Phase 6.1 keeps Phase 6's PRD honest and gives these fixes their own success criteria.

## Scope

In:

- `defineVisillConfig` upgraded so `defineVisillConfig({})` produces a buildable Vite config when run from a scaffolded skill repo. Specifically:
  - `root: 'widget-src'`
  - `build.outDir: 'skill/<skill-name>/assets'` (resolved via `resolveSkillName`).
  - `build.rollupOptions.input: 'widget-src/widget.html'`.
  - `plugins: [viteSingleFile, finalizeBundle, assembleSkill]` wired into the merged config with sensible defaults.
- Test layout migration per ADR 0024:
  - `visill`: move eight `src/*.test.ts` files to `packages/visill/test/`. Rewrite imports.
  - `create-visill`: rename `tests/` to `test/`. Update `vitest.config.ts`.
- Re-green the two failing CI gates from Phase 6.
- ADR 0024 (test layout) already authored; reference it.

Out:

- Any non-test code in `visill` (no SDK API changes).
- Eval-CLI rewrites, description optimizer, additional vendored examples.
- Publish work (Phase 7).

## Risks + mitigations

- **defineVisillConfig override conflicts**: user `vite.config.ts` may pass options that conflict with the new defaults. Mitigation: merge user options on top of defaults, never the other way around, and add tests for each override path.
- **Test migration breakage**: import paths change for every test file. Mitigation: one commit per migration step (test move + import rewrite together per file) so blame is per-file.
- **CI red persists**: if defineVisillConfig fix alone doesn't green the gates, surface that quickly and consider whether the vendored example's vite.config.ts needs to switch to `defineVisillConfig({})` once the defaults land.

## Open questions

- Should the vendored example simplify its vite.config.ts to `defineVisillConfig({})` once the helper is complete? Lean: yes - it demonstrates that the helper actually does the work end-to-end.
- Does `visill-build`'s test directory rename from `test/` to anything? Per ADR 0024 the answer is no; `test/` is the canonical name.

Local quality gate verified pre-commit: 159 tests passing across visill (23), visill-build (22), visill-test (40), create-visill (40), and examples/decision-tree (34). Prettier check, lint, typecheck, and `pnpm -r build` all clean.

CI on `f7ce25d`: `ci` and `scaffolder-windows` green. `scaffolder-smoke` and `vendored-example` red - the same two gates Phase 6 left red. Diagnosis:

- `scaffolder-smoke` builds green now (the Phase 6.1 `defineVisillConfig` + `resolveSkillName` fixes work end-to-end against `file:` workspace links). The test step still fails because the scaffolded skill hits two latent defects the integration gate exposed: `@visill/test#createBundleTests` declares an empty inner describe when no critical literals are passed (Phase 5), and `render.py` reads `schema.json` from `scripts/` while `assembleSkill` writes it to `assets/` (Phase 4). Both predate `3f35ea2`.
- `vendored-example` was already failing on every Phase 6 push. Root cause is a Phase 6 CI/build-script misalignment: the workflow asserts `decision-tree.zip` exists, but `pnpm --filter=./examples/decision-tree build` (which is `vite build`) does not produce the zip; only the separate `build:zip` script does. Local pre-push verification missed this because a stale zip lay around from earlier work. Confirmed pre-existing on runs `25410f8`, `63c4f19`, `ca3d0bb`, and `f7ce25d`.

The four follow-up defects are scoped into PRD 006.2.

## Lessons learned

- **Latent design-time defects compound until they hit a real downstream path.** Three of the four Phase 6.2 carry-overs (resolveSkillName `.ts` loader, `render.py` path, `createBundleTests` empty describe) were all "the unit tests pass but the assembled artefact fails" defects. Each survived because its package's own tests exercised it in isolation. The integration gate is paying off exactly as ADR 0017 promised. Lesson for future phases: when a package ships behaviour that other packages or templates consume, write at least one test against the assembled or consumed shape, not just the package-local fixture.
- **Local verification can lie when stale artefacts linger.** The `vendored-example` zip assertion would have been caught pre-push if local verify had run from a clean tree (no pre-existing zip). For Phase 6.2 and beyond, the local mirror of CI steps should `git clean -fd` (or its equivalent) the example skill's output dir before asserting, so the run actually reproduces the cold-cache CI state.
- **Splitting a fix mid-phase keeps the phase boundary honest.** Phase 6.1 originally targeted `defineVisillConfig` + test layout; Wave C surfaced the `resolveSkillName` `.ts`-loader defect; the user accepted a scope expansion to drop `visill.config.ts`. The resulting three-commit ship is coherent and each commit reviewable on its own. The cost of expanding scope here was small because the defect was on the critical path of Phase 6.1's stated success criteria; deferring to Phase 6.2 would have shipped Phase 6.1 with its own success criteria already failing.
- **TypeScript LSP can lag tsconfig structural changes.** When `packages/visill/test/*.test.ts` first moved out of `include: ["src"]`, the IDE LSP kept flagging vitest globals as missing even after the file system, the test runs, and `tsc --noEmit` all confirmed correctness. Diagnosis took longer than the fix. Lesson: when LSP and tsc disagree on a freshly-restructured project, trust `tsc` plus the test run; the LSP catches up.
- **ADR amendment via supersession is cleaner than in-place edit.** ADR 0011 stayed historically faithful; ADR 0025 captures the new contract with full context (why the original was wrong, what we know now, what we explicitly rejected). Future readers can see both without git archaeology. The same approach should apply to future contract changes.
